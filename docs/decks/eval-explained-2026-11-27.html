模型评测科普 · 2026-11

一次模型评测，
到底在评什么？

一个分数不是“模型跑了一次”，而是 模型 × 考场 × 环境 × 协议 × 运行 × 指标 × 证据 × 治理 的共同结果。少一个要素，这个分数就不可比。

01 封面
总览 · 八要素

分数是八件事的交集，不是模型的一项属性

可信分数 = 模型适配 × 考场覆盖 × 环境一致 × 协议固定 × 运行可靠 × 指标充分 × 证据完整 × 治理有效
Model · 模型
权重版本、adapter、观测/动作契约、serve 镜像
Benchmark · 考场
task suite、覆盖、难度、成功判定
Environment · 环境
本体、仿真器、资产、物理与渲染
Protocol · 协议
种子、集数、步数、精度、随机化
Runtime · 运行
GPU、端口、分片、超时、资源隔离

run id、manifest、原始 episode、checksum

registry、门禁、校准、榜单规则
结论
任一要素缺失，数字只能描述“这次运行”，不能支撑横向比较。
02 总览
要素一 · 模型

“用了哪个模型”至少要回答四层

1 · 身份
模型族、权重 repo、精确 revision、训练数据口径。分支名和 latest 不等于版本。
2 · Adapter
把模型输出变成考场能用的动作；把考场观测变成模型能用的输入。每个模型族都应有显式 adapter。
3 · Serve 契约
镜像 digest、相机顺序、resize、归一化、chunk/queue、reset、healthcheck。
4 · 能力边界
动作维度、状态维度、支持 task、是否需要额外资产。能力不匹配要 fail fast。
例子模型侧适配重点出错表现
X-VLAEE 16D（quat）20D rot6d → 16D quat；三相机；EE planner维度不匹配、全 0 分但无异常
ACT / DPqpos 14DACT 要 640×480 resize；DP 不要 resize；动作块队列观测口径错、动作不动
DB-CogACTqpos 14D，按 task 分头权重子目录、fp16、每 task 独立 serve拉错 task 权重、缺头

关键：上游有 YAML 不等于没有 adapter；YAML 可以是 adapter 的实现素材，但 adapter 仍是稳定扩展边界。

03 模型
要素二 · 考场

考什么，决定这个分数能说明什么

Task suite 与覆盖

模型本考场覆盖能不能直接比
X-VLA5 / 5可覆盖全表
DB-CogACT3 / 5只能比重合 task
ACT / DP2 / 5只能比重合 task

难度不是“更多题”

  • Easy：固定物体/位置，考基本操作能力
  • Hard：纹理、光照、位姿随机化，考鲁棒性
  • 长程任务：交接、装配，考持续规划与恢复

只报 Easy，会把“固定摆位下能成功”说成“能操作”；不披露覆盖，会把“没权重”伪装成“模型不行”。

04 考场
要素三 · 环境

仿真器、本体、资产，都是“考卷”的一部分

层管什么典型差异不一致的后果
本体 Embodiment关节数、动作空间、相机、夹爪14D qpos / 16D EE / 7D 单臂动作维度或语义错
仿真后端物理、碰撞、渲染、随机化SAPIEN（RoboTwin/ManiSkill）
MuJoCo（LIBERO/RoboCasa）		同一模型分数不可直接横比
场景资产物体、桌面、材质、光照、URDF资产 revision、挂载路径、实体数量场景缺失、行为漂移
渲染与资源GPU、EGL/CUDA、shared memorySAPIEN 长驻进程可能 renderer 崩episode error、假失败
环境一致
同镜像 digest + 同资产 revision + 同随机化配置，分数变化才能归因给模型或协议。
环境不一致
即使模型没变，材质、相机、物理参数、渲染后端变化也会移动成功率。

设计含义：考场 adapter 管 task 与判定；backend profile 管镜像、资产、渲染和资源。不要把这些全塞进模型 adapter。

05 环境
要素四 · 协议

协议就是“这场考试的统一规则”

旋钮它控制什么改了会怎样必须记录
种子 Seeds场景随机化与 episode 顺序同模型分数也会变逐集种子表
集数 Episodes统计样本量 n置信区间宽度目标 n / 实际 n
难度 Protocol固定 / 随机化 / 干扰考的是不同能力protocol_version
步数上限最长允许执行步数长程任务被截断max_steps
精度与栈fp16 / fp32、镜像、planner数值与动作轨迹变化镜像 digest / dtype
重复轮 Replicate同配置再跑一遍估计运行方差r2 / r3 标签
协议版本 = 考场 + 集数 + 种子策略 + task_config + max_steps + harness + 镜像 digest

任一旋钮变化，都应该生成新版本；旧结果冻结，不覆盖。否则“同一个 92%”其实不是同一件事。

资源隔离
serve 与环境分卡；端口、容器名、GPU 必须可参数化。写死 8000 就没法并行。
分片与吞吐
分片提高吞吐，但过多会 OOM 或 renderer 崩。X-VLA 用 4，qpos 模型用 8。
超时与恢复
超时是协议的一部分；恢复要从持久化 manifest，不依赖本机临时目录。
失败隔离
单 episode 失败不应中止整场；error 与 fail 必须分开。
可观测性
日志、容器状态、GPU、episode 进度都要能定位“卡在哪”。
运行不是细节
端口冲突、错卡、旧容器、残留 results，都会让分数失真。
07 运行
要素六 · 指标

成功率只是一个分子/分母，后面还有四层信息

成功率 = success episodes / terminal episodes × 100%
指标回答什么例子缺了会怎样
点估计这次大概多少分46/50 = 92%看起来精确，其实有噪声
样本量 n这个数有多稳n=50 / n=5000n=12 和 n=50 被混着比
Errors是模型失败还是基础设施坏了0 error / 3 error infra 故障被当成模型能力
95% CI不确定性范围92% → [81.2%, 96.8%]把 4pp 差异当成结论
Steps / Time成功得多快、多稳平均步数、最大/最小耗时忽略长尾与卡死
Failure taxonomy为什么失败grasp / timeout / model_act无法定位改进方向

一个可信的格子至少是：K/N + errors + 95% CI + 平均步数 + 协议版本。

08 指标
统计常识 · 为什么需要重复轮

92% 一定比 80% 好吗？先看不确定性

ACT · click_bell
46/50 = 92%
95% Wilson CI：[81.2%, 96.8%]
DP · click_bell
40/50 = 80%
95% Wilson CI：[67.0%, 88.8%]
两个区间有重叠：[81.2%, 88.8%]
单轮 n=50 只能描述差异，不能直接宣布 ACT 显著更强。
n 小
区间宽，偶然性大；单集噪声可达 ±100pp。
只跑一轮
不知道多少差异来自运行方差，多少来自模型。
补 r2 / r3
同配置重复，估计方差，再做合并与显著性判断。

科普结论：点估计是“观测值”，置信区间是“我们有多确定”；两者要一起读。

  • 不可变：checkpoint 对象不覆盖，重复上传按 checksum 去重
  • 可恢复：manifest 记录已 committed episode
  • 可重算：aggregate 能从原始 episode 重新生成
  • 可审计：模型 revision、镜像 digest、协议版本都在 manifest 里

只有 aggregate 没有原始数据，等于只有结论没有证据；只能信，不能验。

13 全流程
避坑 · 最常见的八类失真

很多“模型不行”，其实是评测坏了

现象根因怎么发现怎么防
全 0 分、无异常观测 resize / 归一化 / 相机错单集 smoke + 动作/观测日志adapter 契约测试
动作不动随机权重、chunk 队列空、维度错strict load + 有限值检查权重 pin + spec 校验
结果突然变好旧 results/ 残留混入run id / 文件时间线新 run 清盘 + 独立目录
整轮 error端口冲突、旧 serve、GPU 抢占容器/端口/GPU 状态参数化资源 + 串行门禁
长任务恒 0超时上限太短episode 耗时分布step/time 协议匹配
partial 被当正式n 不齐仍生成榜单manifest / n_targetn == 目标才进榜
中途失败丢数据只在最后上传OBS 缺已完成 episode每集 checkpoint
同名分数不可比协议/镜像/种子未记录manifest 缺字段protocol_version + digest

先证明“考试没坏”，再讨论“模型好不好”。顺序反了，结论一定是假的。

14 失败案例
拿来就能用 · 12 个问题

看到一个分数，先问这 12 个问题

  1. 测的是哪个权重 revision？
  2. 用了哪个 adapter / serve 镜像 digest？
  3. task 覆盖多少？缺的 task 为什么缺？
  4. Easy 还是 Hard？随机化了什么？
  5. 种子策略和逐集种子表在哪？
  6. n 是多少？跑满目标了吗？
  1. errors 是 0 吗？fail 和 error 分开了吗？
  2. 95% CI 有多宽？差异超过噪声了吗？
  3. 有没有 r2 / r3 重复轮？
  4. 原始 episode / sqlite / 视频能追到吗？
  5. 中途失败后，已完成数据还在吗？
  6. 过门禁了吗？和官方校准差多少？
答不全 → 只能说“这次跑出了这个数”
答得全 → 才能说“这个数可以比较、引用、复核”
15 检查清单
总结 · 一句话记住

模型评测不是“跑个分”，
是生产一份可采信的证据。

可定义
模型、考场、协议说清楚
可复现
同参数能跑出同数
可审计
每个数追得到原始证据
可比较
同口径、带 n 与不确定性

八要素缺一个，分数就只是“观测”；八要素齐了，分数才是“结论”。
