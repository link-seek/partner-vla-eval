02 已建成
为什么必须自己做 · 对标 CloudRobo

平台解决"能不能跑"，尺子解决"可不可比"

以华为云 CloudRobo 公开文档为样本（未控制台实测）：它强在一站式与数据体检；模型评测的默认值决定了我们的题测不了。

CloudRobo 的默认

  • 考场：任务集仅 LIBERO，RoboTwin 不在列表
  • 时长：每轮 0–300 s（默认 90），文档未给放宽路径
  • 读数：成功率 + 耗时，无 error 分类、无置信区间
  • 复现：场景种子单值，未提官榜校准

我们的尺子

  • 考场：RoboTwin 全 50 task，长程任务按 step 上限跑完
  • 读数：n / errors / 95% CI / 平均步数，逐格
  • 复现：逐集种子 + protocol_version + digest
  • 校准：对官榜 −1.40pp，第 15 道门守

公平地说：它的数据评测（安全/效率/平稳性三维、20+ 指标、PDF 报告）比我们深；我们赢在模型分数的可比与可复核。

03 为什么自己做
风险 · 不写出来，别人也会问

现在最缺的不是门禁，是使用

01 外部引用 = 0
所有证据都是自证：自己跑、自己写、AI 读者也是临时证据。
尺子的价值 = 被引用次数，现在是 0。
02 统计力撑不起"谁更强"
n=50、单轮，噪声带约 ±8pp。
现在只能回答"这个配置多少分"，不能回答"模型 A 是否优于 B"。
03 数据质量维度薄
S1 只有格式校验 + 统计（2750 文件 / 38 万帧 / 0 坏文件）。
安全、效率、平稳性三维还没建。
