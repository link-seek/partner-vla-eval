模型评测，
到底在评什么？

从 RoboTwin 2.0、LIBERO、CALVIN、SimplerEnv 和 vla-eval 的论文出发，拆开“跑分”与“评价模型”的区别，再给出一套普通人也能照着做的评价方法。

01 封面
先看结论 · 三层答案

一个分数只是观测；模型评价是一组受控实验

1 · Benchmark result
一个 checkpoint，在一套协议和一个考场上跑出多少分。
回答：这次是多少。
2 · Controlled comparison
保持其他条件不变，只改数据、方法或环境，比较差值。
回答：哪个因素带来了变化。
3 · Model evaluation
多考场、多协议、多训练条件，加基线、重复、失败分析和边界。
回答：模型擅长什么、何时失效。
论文里的“模型评测” = 研究问题 + 对照设计 + 指标 + 统计 + 失败分析 + 适用边界

如果只说“模型考了 92%”，那是一次跑分；如果比较不同数据、训练方法、难度和考场，才是在评价模型。

名词解释checkpoint = 固定权重；受控对照 = 只改一个关键变量；能力画像 = 模型在不同任务/条件下强弱的整体描述。
02 先看结论
论文比较 · 它们到底在评什么

四个 benchmark，四种不同的研究问题

论文核心问题怎么设计主要指标给我们的启示
RoboTwin 2.0数据多样性与领域随机化能否提升双臂操作鲁棒性50 task；50 clean demos；Easy/Hard 各 100 rollouts；仿真→真机成功率；Hard−Easy；真机提升数据与环境要作为自变量
LIBERO策略能否迁移知识、避免遗忘130 task / 4 suite；每 task 50 demos；3 seedsFWT / NBT / AUC指标要匹配研究问题
CALVIN能否把语言指令组合成长程操作34 task；4 环境；1000 条五步指令链；多种 train→test splitMTLC；LH-MTLC 1–5 步成功率单题分数会隐藏组合失败
SimplerEnv仿真能否可靠替代真机评测真机/仿真配对评测；约 1500 episodes；视觉匹配+系统辨识成功率；Pearson r；MMRV评测工具本身也要被验证
共同点：都不是“拿一个模型跑一次”，而是固定条件、改变因素、设计指标、重复实验、分析边界。

下一篇 vla-eval 把这些考场统一起来，并进一步回答：跨 benchmark 的可复现评价应该怎么做。

名词解释suite = 一组有共同目的的 task；rollout = 一次完整尝试；split = 训练/测试环境划分；指标 = 你用什么数来判断好坏。
03 论文比较
论文案例 1 · RoboTwin 2.0

它评的不是“模型聪不聪明”，而是“数据能不能带来鲁棒性”

标准 benchmark 协议

  • 50 个双臂 task，Aloha AgileX 本体
  • 每 task 50 条 clean demos 用于训练
  • 每 task 在 Easy / Hard 下各跑 100 rollouts
  • Hard 加入杂乱场景、光照、背景纹理、桌高变化

真正的评价实验

  • 32 task、两种数据：无随机化 vs 领域随机化
  • RDT / Pi0 分别训练，比较 5 个未见 task
  • RDT：14.8% → 16.6% → 25.4%
  • Pi0：21.0% → 20.6% → 29.8%

论文的做法是：让数据口径成为自变量，让 Easy/Hard 和真机场景成为检验泛化的因变量。

04 RoboTwin
论文案例 2 · LIBERO

它评的是“知识迁移与遗忘”，所以不能只报成功率

任务设计

  • 130 个语言条件操作 task
  • Spatial / Object / Goal 各 10 task，分别隔离空间、物体、目标知识
  • LIBERO-100：90 个短程 task 用于预训练，10 个长程 task 用于 downstream 评测
  • 每 task 提供 50 条人工遥操作 demos

指标与统计

  • FWT：学新任务时，旧知识帮了多少
  • NBT：学新任务后，旧任务退化了多少
  • AUC：把学习过程中的表现综合成曲线下面积
  • 3 seeds，均值±标准误；两尾 t-test，p=0.05
研究问题不同 → 指标不同：
RoboTwin 问“成功率与鲁棒性”；LIBERO 问“迁移、遗忘与学习曲线”。

论文甚至发现：简单监督预训练可能伤害后续终身学习。若只看最终成功率，这个结论根本看不出来。

来源：LIBERO，arXiv:2306.03310，§4.2、§5.1–5.2。

名词解释FWT = forward transfer，前向迁移；NBT = negative backward transfer，负向后向迁移；AUC = 曲线下面积；遗忘 = 学新任务后旧任务变差。
05 LIBERO
论文案例 3 · CALVIN

单任务 53.9%，五步连续任务只有 0.08%

任务
34 个基础 task，4 个环境 A/B/C/D，7-DoF Franka，PyBullet。
数据
24 小时自由 play 数据，约 20K 语言指令；语言只标注约 1%。
泛化 split
D→D；ABCD→D；ABC→D（训练三环境、测试未见环境）。
评测怎么测基线结果说明什么
MTLC 单任务34 task，每 task 10 rollouts；测试语言是未见改写53.9%单题能力看起来不错
LH-MTLC 长程1000 条指令链，每条连续 5 个 task1 步 48.9%；5 步 0.08%组合、状态转移、语言 grounding 严重不足

如果只报 53.9%，会以为模型“会操作”；加入连续任务，才看到它不会把技能组合成长程行为。

来源：CALVIN，arXiv:2112.03227，§III-C。

名词解释MTLC = 多任务语言控制；LH-MTLC = 长程多任务语言控制；grounding = 把“蓝色方块”这类语言对应到真实物体；split = 训练/测试环境组合。
06 CALVIN
论文案例 4 · SimplerEnv

它先问：仿真这把尺子，本身准不准？

配对真机/仿真评测

  • Google Robot 与 WidowX 两种真实本体
  • 真机与仿真各约 1500 episodes
  • 比较不同策略的排名与表现是否一致
  • 分析光照、背景、相机位姿、干扰物、桌纹等分布偏移

两种弥合差距的方法

  • Visual Matching：绿幕替换真实背景、贴真实纹理
  • System Identification：用少量真机轨迹校准仿真控制参数
  • 提出 MMRV：衡量仿真把真机策略排名弄错了多少
评测 simulator = 比较 sim 分数与 real 分数的相关性、排名一致性、对分布偏移的敏感性。

这篇论文提醒我们：模型评价之前，要先证明“考场”没有系统性骗人。

来源：SimplerEnv，arXiv:2405.05941；项目页 simpler-env.github.io。

名词解释Pearson r = 线性相关系数；MMRV = 平均最大排名违反度，越低说明仿真排名越接近真机；系统辨识 = 用真实数据校准模拟器参数。

08 vla-eval
从论文提炼 · 通用评价流程

评价一个模型，按这七步走

1 问题要证明什么？
→
2 变量改什么、固定什么？
→
3 基线和谁比？
→
4 考场同分布/OOD/跨考场
→
5 指标成功率之外还要什么？
→
6 统计n/重复/区间/显著性
→
7 结论证据、失败、边界
输入
研究问题 + 模型/数据/方法/预算 + 基线
过程
受控实验 + 多条件评测 + 原始证据留存
输出
能力画像 + 效应量 + 不确定性 + 失败模式 + 适用边界

论文不会问“怎么把 shell 跑完”，它们先问“什么实验能回答研究问题”。工程只是让实验可执行、可复现。

名词解释OOD = 分布外；效应量 = 差异有多大；显著性 = 差异是否超过随机噪声；边界 = 结论不能外推到哪里。
09 通用流程
方法 1 · 定义研究问题

先把“模型好不好”拆成可验证的问题

能力
零样本能不能操作？长程组合行不行？失败恢复呢？
数据
50 vs 550 条、clean vs randomized，数据多样性值多少分？
方法
ACT vs DP、全参 vs LoRA，同预算谁更有效？
鲁棒性
换光照、材质、位姿、物体后，性能掉多少？
泛化
跨考场、跨本体、跨场景、仿真到真机，结论还成立吗？
效率
成功率、延迟、训练成本、样本效率怎么权衡？
问题模板：在 [条件] 下，模型 [M] 相对 [基线 B]，在 [任务/指标] 上表现如何，差异是否超过噪声？
名词解释claim = 想证明的一句话；零样本 = 不在目标 task 上微调；样本效率 = 达到同样效果需要多少数据。
10 定义问题
方法 2 · 实验矩阵

固定模型与预算，只让要研究的变量变化

层固定/记录可变化为什么
模型checkpoint、revision、架构、动作空间不同基模分清模型与权重
数据来源、清洗、数量、任务分布clean/randomized、50/550回答数据价值
方法ACT/DP、超参、seed、日志全参/LoRA、optimizer避免混淆归因
预算优化步数、GPU 小时、精度等步数/等成本固定 epoch 会偏袒大数据
协议task、Easy/Hard、种子、max_steps、n不同考场/难度保证可比
R01：ACT/DP × {50 clean, 50 clean+500 randomized} × {Easy, Hard} × 5 task
= 40 格；每格 50 episode，共 2000 episode。
名词解释自变量 = 主动改变的因素；控制变量 = 保持不变的条件；算力预算 = 训练步数/GPU 小时/成本。
11 实验矩阵
方法 3 · 基线与消融

没有参照，差异只是“看起来不同”

基线

  • 官方 checkpoint
  • 简单策略/随机动作
  • 同模型不同条件
  • 同任务历史最佳

实验设计

  • 单因素消融：只改一个因素
  • 因子实验：看因素交互
  • 负对照：证明设置生效
  • holdout：防止挑题
设计能回答常见错误
只换数据 A/B数据的独立贡献同时换步数、精度、考场
ACT/DP × A/B数据收益是否依赖模型族只看总体均值
RoboTwin + LIBERO能力是否跨考场迁移合成一个总分
名词解释基线 = 比较参照；消融 = 拿掉/替换因素看贡献；交互 = A 的效果在 B 下不同；holdout = 不参与调参的保留集。
12 基线与消融
方法 4 · 多考场与泛化

一个考场的高分，不等于模型有泛化能力

评测域怎么设计能说明不能说明
同分布同任务/场景/数据口径是否学会目标能力换环境行不行
分布外 OOD换物体/材质/光照/位姿鲁棒性跨本体一定行
跨考场RoboTwin + LIBERO + …能力迁移合成一个总分
跨本体不同关节/相机/动作embodiment 泛化adapter 无偏差
Sim2Real仿真训练、真机测试真实外部效度仿真可替代真机
覆盖度 = 考了多少题；泛化 = 没见过的条件还能不能用。两者分开报告。
名词解释In-distribution = 接近训练分布；OOD = 分布外；embodiment = 机器人本体；Sim2Real = 仿真到真实。
13 多考场与泛化
方法 5 · 统计与重复

论文用 seeds、区间和显著性，不靠一句“更高”

样本量 n
RoboTwin 100 rollouts/task；LIBERO 3 seeds；SimplerEnv 288 episodes。
不确定性
LIBERO 报均值±标准误；CALVIN 用长程成功率分布；我们每格报 95% CI。
显著性
LIBERO 用两尾 t-test，p=0.05；多重比较要防止偶然显著。
聚合
总体平均会被简单题带偏；要同时看 per-task 与 macro-average。
重复轮
同配置 r2/r3，区分模型差异与运行方差。
表述
“未观察到显著差异”不等于“证明没有差异”。
名词解释标准误 = 均值的不确定性；p-value = 在“没有差异”假设下看到当前结果的概率；macro-average = 每 task 先算再平均。
14 统计与重复
方法 6 · 失败分析

论文靠失败模式解释分数，不只看平均值

量化

  • per-task 热力图与长尾
  • fail/error/timeout 分开
  • 步数、耗时、重试分布
  • 最难 task / 最坏种子

定性

  • 视频：滑落、碰撞、振荡、停住
  • 观测/动作：输入与维度是否错
  • 训练日志：过拟合、数据污染
  • 归因：感知/规划/控制/环境
同分 80%模型 A模型 B结论
能力画像简单题 100%，难题 40%简单题 85%，难题 75%B 更均衡
失败方式多为 timeout多为 grasp miss改进方向不同
名词解释热力图 = 用颜色看每 task 表现；长尾 = 少数难题拉低整体；grasp miss = 没抓到；timeout = 超时。
15 失败分析
方法 7 · 结论模板

结论必须同时写清证据、条件和边界

在 [模型/权重] + [训练条件] + [考场/协议] + [资源] 下，
相对 [基线]，[指标] 变化 [效应量 + 区间]；
适用于 [范围]，不适用于 [未测条件]。
不合格
“ACT 比 DP 好。”
“数据越多越好。”
“这个模型泛化强。”
可检验
“V100 fp32、同 40k 步、RoboTwin 5 task 下，数据 B 对 ACT Hard 成功率提升 X pp（95% CI …），对 DP 未观察到同样收益；不跨本体、不跨真机。”
名词解释边界 = 结论适用条件；可检验 = 别人能用同样数据/协议复核；未观察到 ≠ 证明没有。

18 模型与适配器
工程 2 · 考场与环境

考卷由 task、本体、仿真器和资产共同组成

层管什么差异例子不一致后果
Task suite题目与覆盖RoboTwin 50 / LIBERO 130覆盖面不同，不能混排
本体关节、动作、相机14D qpos / 7D EE维度或语义错
仿真后端物理、碰撞、渲染SAPIEN / MuJoCo / PyBullet分数不可直接横比
资产物体、材质、URDFrevision、挂载、实体数量场景漂移
同模型 + 同协议 + 不同环境 = 不同考试；先固定考场，才能归因给模型。
名词解释suite = 一组 task；URDF = 机器人结构文件；SAPIEN/MuJoCo/PyBullet = 三种仿真后端；资产 revision = 场景文件版本。
19 考场与环境
工程 3 · 协议与运行

协议决定“怎么考”，运行决定“有没有考坏”

协议

  • 种子与逐集种子表
  • 目标 n / 实际 n
  • Easy/Hard 与随机化
  • max_steps / timeout
  • 精度、镜像、重复轮

运行

  • serve 与环境分卡
  • 端口/容器名参数化
  • 分片与资源隔离
  • 失败隔离与恢复
  • 日志、GPU、episode 进度
protocol_version = 考场 + n + 种子策略 + task_config + max_steps + harness + 镜像 digest
名词解释seed = 随机种子；max_steps = 单集最多步数；shard = 分片进程；resume = 从已完成点继续；fail fast = 不烧卡就拒绝错配置。

25 常见失真
拿来就用 · 12 个问题

看到一个模型结论，先问这 12 个问题

  1. 研究问题是什么？
  2. 权重 revision 是哪个？
  3. 改了哪些变量，固定了哪些？
  4. 基线是谁？
  5. task 覆盖多少？
  6. 同分布还是 OOD？
  1. n / seeds / 重复轮是多少？
  2. 指标匹配研究问题吗？
  3. 区间/显著性看了吗？
  4. 失败模式是什么？
  5. 原始证据能追到吗？
  6. 结论边界写清了吗？
答不全 → 只能说“这次跑出了这个数”
答得全 → 才能说“这是对模型能力的评价”
名词解释OOD = 分布外；seed = 随机种子；重复轮 = 同配置再跑；基线 = 比较参照；边界 = 结论适用范围。

总结 · 一句话记住

模型评测不是“跑个分”，
是用受控实验回答一个研究问题。

有问题
先定义要证明什么
有对照
变量、基线、条件
有统计
n、区间、重复
