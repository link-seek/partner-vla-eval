01 封面
我们是什么

我们造尺子，不卖读数

别人训模型，我们给分。分数怎么来、能不能复核，由底座决定——所以我们证明的不是"我们的分数对"，是"同一把尺子量谁都一样，而且你能自己量"。

可复现
同参数同数：协议版本 + 镜像 digest + 权重 revision
可审计
每一格追得到：run id → aggregate → sqlite → 逐集 jsonl
可扩展
官方没支持的模型/口径，我们接得上（见第 4 页）
诚实
不可比的地方自己先说：覆盖 5 vs 3、n 与误差、中途不进榜

我们不要求你信我们的分数 —— 我们提供让你自己验的一切。

02 我们是什么
我们的方案 · 架构

三层：内核用上游，中间两层是我们做的

层谁做内容
评测内核上游 allenaiharness CLI（run / serve / export / test）、benchmark 适配层、spec 体系

分工一句话：上游负责"怎么评"（协议与接口），我们负责"能不能跑、跑完怎么收、收完怎么验"。

12 微调轴 下一阶段
支柱五-a 延伸 · 官方基线接入 已闭环

官方 ACT / DP 也能跑了：2/5 覆盖，两次 smoke 零报错

为什么不是"照抄配置就能跑"（5 条硬契约）

  • 相机：考场 D435 出 240×320，ACT 官方要 640×480；DP 反过来不许 resize
  • 键位：DP 显式读三路相机（缺一路 KeyError），但 encoder 只消费 head_cam

  • 路径：DP 用相对 CWD + 4 段 ckpt 目录（与 HF 的 3 段不同）
  • 依赖：DP 缺 8 个包（hydra/dill/einops/zarr/numcodecs/numba/atomics/diffusers），钉版烘进镜像

14 Easy vs Hard
工程化 · 治理 已落地

评测本身也要有版本和门禁：四类归属 + 15 道门

四类，各有住址与生命周期

  • 产物：OBS 大件 + 仓内索引；按 protocol_version 冻结
  • 基础设施：镜像/脚本/workflow；tag 不可变、一次性件不许进 main
  • 文档：站点=教程；Discussion=过程；ADR=决策（接受后冻结）
  • 流程：CONTRIBUTING + PR 模板 + CODEOWNERS + main 保护

门禁由机器判定

  • run_all.py 15 项：路径/契约/registry/镜像/基础设施/版本/协议/报告/覆盖/榜单/统计/采集/适配器/校准/文档
  • 直推 main → 422 must be made through a pull request（实测）
  • 镜像清单 15 条，--remote 逐条向 SWR 校验 digest
  • docs 站点真构建（jekyll --strict_front_matter，60 页含主题资源）

为什么算"能力"：没有这些，分数不可复现——同配置重跑、换人跑、三个月后跑，都要对得上。
