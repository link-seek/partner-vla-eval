# CloudRobo 评测能力读后：它做体检，我们做尺子

- 日期：2026-11-26
- 对象：华为云「具身智能开发平台 CloudRobo」（西南-贵阳一）
- 结论一句话：**它的数据评测比我们深，它的模型评测比我们浅；两边不是同一层产品，别正面比"平台"。**
- 证据口径：全部来自公开文档（support.huaweicloud.com），逐条附出处与文档更新时间；未登录控制台实测，未做功能验证。

## 1. 它是什么

CloudRobo 是"一站式全托管"具身平台：具身广场（预置资产）、数据准备、模型开发（Notebook/训练/仿真强化/真机强化/模型评测）、运行管理（模型部署/机器人接入/调度）、空间资产。评测只是其中两个模块：

- **数据准备 > 数据评测**：评"数据集好不好"（质量 + 多样性）。
- **模型开发 > 模型评测**：评"模型行不行"（仿真里跑任务，成功率 + 耗时）。

配套 API 有 `CreateSkillEvalJob`（技能评测）与 `CreateDataEvaluatingTaskV2`（数据评测），说明评测是平台一等公民，可被流水线调用。

## 2. 模型评测：能力清单

| 维度 | 现状 | 出处 |
|---|---|---|
| 评测类型 | 单任务（1 个模型服务 × 1 个仿真场景）；任务集（Benchmark） | 模型评测流程 |
| Benchmark 覆盖 | **任务集目前仅支持 LIBERO** | 查看评测任务详情（表 3「任务类型：目前仅支持 Libero」） |
| 评测次数 | 1–50 次/任务 | 快速入门 表 5-1 |
| 超时 | 0–300 秒 | 同上 |
| 随机化种子 | 0–10000，"同一场景同种子得到一致的场景随机化行为" | 同上 |
| 场景随机化 | 物体位姿 / 环境纹理（基础+污损）/ 室内光源，可在仿真环境里改并"全局随机与预览" | 快速入门 5.2 节 |
| 启动方式 | 自动启动；或手动进仿真环境调观测相机再启动 | 同上 |
| 回放视频 | 失败轮次全存；成功但"长耗时"（>均值 75%）存；成功按采样比例存 | 同上 |
| 单任务指标 | **执行成功率（成功次数/总次数）**、执行时间（成功最大/最小/平均/总） | 详情页 表 2 |
| 任务集指标 | 总体成功率、分套件成功率、子任务回合与成功率 | 详情页 表 4 |
| 前提 | 模型必须**先部署成"运行中"的在线服务**；自有模型+自有本体需先做映射，否则无法评测 | 快速入门 约束限制；FAQ 6.3.3 |
| 支持本体 | jaka、SO101、星海图 R1、千寻、青龙 | 快速入门 FAQ |
| 算力 | 公共资源池（不收费、限配额）或专属资源池（自购 CCE / 仿真单元）；GPU 不可见，仅用于仿真类任务 | 快速入门 计费影响；FAQ 5.6 |

**读出来的三个硬约束**（对我们最有信息量）：

1. **没有 RoboTwin**。平台任务集只挂了 LIBERO；RoboTwin 那套双臂 ALOHA 场景不在名单里（CloudRobo 团队自己在 RoboTwin 榜上交了 WM 结果，但那是线下跑榜，不是平台能力）。
2. **单次 300 秒上限**。长时任务（比如交接、装配类长程操作）在这个口径下要么跑不完、要么被截断，成功率不可比。
3. **指标只有一个数**：成功率 + 时间。没有逐 episode 的 error 分类、没有多种子聚合、没有置信区间、没有协议版本号。种子是"场景级随机化因子"，不是"每 episode 种子表"。

## 3. 数据评测：这块它比我们深

两套算子：**质量评测**、**多样性评测**（LeRobot V2.1/V3，自动转 V3）。

质量评测按三维打分，输出 PDF 报告（评估综述 / 关键指标 / 典型轨迹 / 高阶分析 / 附录），每条规则给「良好 / 中等 / 严重」：

| 维度 | 代表指标 | 阈值示例 |
|---|---|---|
| 安全 | 最小关节限位余量 `m_min`、末端最大线/角速度、关节最大角速度、最大加速度 | `m_min.median < 0.01` 中等；`≤ 0` 严重；`s_max.p95 > 0.20/0.25 m/s` 中/严重 |
| 效率 | 执行时长、最大冻结时长 `T_freeze`（末端速度 < 0.005 m/s 持续）、路径效率指数 `PEI`、抓取尝试数 | `T_freeze.p95` 5–10 s 中等，>10 s 严重 |
| 平稳性 | 动作抖动 `J_act`、位置残差抖动 `sigma_p*`、最大 Jerk `J_max`、LDLJ | `J_max.p95 > 3.0/4.5 m/s³` 中/严重；`J_act.p95 > 5.0/5.5` 中/严重 |

另有**数据清洗算子**：NaN/Inf、过短 episode、黑帧/模糊帧、动作突变、状态-动作对齐，逐 episode 给 KEEP/TRIM/DROP，可产出清洗后数据集。

支持机型：R1、SO101、A2D、CM_V2_SL、K4PRO、SH（青龙）；数据评测与真机接入文档标注**仅西南-贵阳一**。

对照我们 S1：我们目前是"格式校验 + 统计"（2750 文件 / 38 万帧 / 0 坏文件）。**它的安全/效率/平稳性三维是我们没有的**，而且阈值是公开写死的——这点值得抄，也值得质疑（阈值没有按任务/本体校准，属于经验值）。

## 4. 与我们对照

| 能力 | CloudRobo | 我们（partner-vla-eval） |
|---|---|---|
| 产品形态 | 平台工作台（数据→训练→部署→评测→真机） | 评测底座（尺子 + 编排 + 门禁 + 校准） |
| Benchmark | 平台内仅 LIBERO；单任务自定义场景 | RoboTwin 官方 50 task，ACT/DP 已覆盖 2/5，50 集参考 |
| 与官榜对齐 | 无校准机制 | X-VLA 50-task 66.56% vs 官方 67.96%（−1.40pp），第 15 道门守 |
| 指标深度 | 成功率 + 耗时 | n、errors、步数、95% CI、逐集 aggregate 入库 |
| 可复现 | 场景种子 0–10000（单种子） | 每 episode 种子表 + `protocol_version` + 镜像 digest |
| 门禁 | 无（平台侧无 CI 概念） | 18 道门，坏结果不许进表 |
| 接入成本 | 必须部署在线服务 + 模型-本体映射 | 任意模型接 adapter（`ActionQueue` / `policy_profiles`），1 集 smoke 即验 |
| 数据质量 | 三维 20+ 指标、PDF 报告、清洗 KEEP/TRIM/DROP | 格式校验 + 帧数/文件统计 |
| 长时任务 | 单次 300 s 上限 | 按 step 上限（800），handover_block 实测 6–7 s/step 也能跑完 |

一句话：**它评"这套资产能不能用"，我们评"这个模型到底多少分、这个分可不可比"。**

## 5. 对汇报/路线的影响

1. **别把它当竞品打**。它是平台，卖的是"一站式"；我们卖的是"可复现的读数"。汇报里定位成互补：平台负责把数据、模型、本体管起来，尺子负责让分数可横向比。
2. **数据评测这块可以借，但要带校准**。安全/效率/平稳性三维 + LDLJ/冻结时长/PEI 是成熟的度量语言，直接借维度名，阈值我们自己按 RoboTwin 数据分布标（它没做这件事，正是我们的空间）。
3. **它的三个硬约束就是我们的卖点**：无 RoboTwin、300 s 上限、单指标无置信区间。这三条写进 deck 的"为什么需要独立尺子"，比讲理念有力。
4. **RoboTwin 榜上 CloudRobo-WM 95.28 / 82.68（co-train）**——说明对方团队认可这个考场，只是平台没接。未来若谈合作，"把 RoboTwin 接进 CloudRobo 任务集"是可谈的具体切口。
