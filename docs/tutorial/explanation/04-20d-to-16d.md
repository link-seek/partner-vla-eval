# 20D 转 16D：serve 侧的动作转换

> 给复现者：X-VLA 输出 20D，RoboTwin 只认 16D，转换在 serve 侧做。
> 时间：10 分钟 ｜ 前置：`quickstart`。
> 你将得到：转换规则、代码位置、复现方法。

## 现象（一句话）

X-VLA 模型输出统一 20D 双臂 EE6D 动作。RoboTwin 的 `take_action(..., "ee")`
要 16D（双臂各 8D）。两者之间差一次转换，不做则维度对不上。

## 证据

easy50 报告的 serve/run 配置即证据：

- serve：`configs/serve-robotwin.yaml`（`benchmark_profile: robotwin`，
  `output_action_dim: 16`）
- run：`run-robotwin-chunk.yaml`（`action_type: ee, send_state: true`）
- 结果：[`xvla_robotwin-easy50.json`](https://github.com/link-seek/partner-vla-eval/blob/main/docs/reports/xvla_robotwin-easy50.json)（66.6%/5000ep 零 error）

## 机理

转换在 serve 侧（`src/vla_eval/model_servers/xvla.py`，上游 #168 合入后的逻辑），
按官方 `evaluation/robotwin-2.0/client.py` 逐项对齐：

| 源（20D，单臂 10D） | 目标（16D，单臂 8D） | 规则 |
|---|---|---|
| pos3 | pos3 | 直通 |
| rot6d（6D） | quat（4D，xyzw→wxyz 序以官方为准） | Gram-Schmidt 正交化 → 四元数 |
| gripper（1D，sigmoid 后） | gripper（1D） | `1 - 2 * (sigmoid > threshold)`，RoboTwin 侧再 clip 到 [0,1] |

proprio 同理反向：首推理用环境 16D 末端位姿转 20D，后续用上一次预测的
`[pos3, rot6d6, gripper]`（闭环，和官方 eval loop 一致）。

单臂榜（LIBERO/Simpler/CALVIN）走另一条：取第一臂 10D → 转 7D
`[pos3, axisangle3, gripper]`。profile 靠 `benchmark_profile` 切换，不要手写分支。

## 复现者怎么复现/避坑

1. **`output_action_dim` 必须和 benchmark 对上**：16 给 RobotWin，7 给单臂榜。
   错了就是维度错配，症状和口径错一样（跑满零分零异常）。
2. **gripper 阈值是 profile 定的**（robotwin 0.7），不是模型定的。6 个全塌 task
   （blocks_ranking×2、put_bottles_dustbin、stack×2，步数跑满）疑 gripper 语义，跟踪中。
3. **不要在 benchmark 侧转**：转换是 serve 的职责，benchmark 只认 16D 原生布局。
