# 09 社区协作：从发现问题到合入上游

> 版本：v2.0（2026-10-22，#168/#169 闭环后重写；v1.0 只写到“已提 issue”）

## 标准四步（本仓实测跑通两轮）

1. **发现问题（证据先行）**：spec warning 截图 + 对照数据（X-VLA 0% vs 官方 70%，DB-CogACT 同链路 92% 正常 = 排除链路本身）+ 双边根因定位。没这三件不提 issue。
2. **询求作者确认**：issue 里给复现路径 + 参数化方案（别只抛问题）。#166 当天收到维护者 "Happy to receive PR"；#169 当天收到绕行钥匙（换 checkpoint）。**先等确认再写大补丁**——方向错了白干。
3. **解决问题（本地验证）**：fork → 分支 → GPU 实测。#168 的 EE 链路 6ep 全跑满零 ERROR 才敢标 ready；#169 按钥匙换 checkpoint 重跑出分才关。
4. **提交跟进**：PR  description 写清验证矩阵（环境/镜像/种子/分数）；review 意见 24h 内回；合并不了就留 fork 分支 + 文档注明（#168 现状）。

## 反模式（本仓踩过）

- **猜作者意图直接开干**：SmolVLA 映射照 pi05 猜，10/10 全崩——先问后写。
- **无验证关 issue**：#169 差点凭回复就关；规矩：无 run 链接不关。
- **改 server 还是改 benchmark 拍脑袋**：原则是不动官方件（X-VLA 权重/镜像原样用），转换跟口径走。两边都通时，写进 PR discussion 让 reviewer 选。
