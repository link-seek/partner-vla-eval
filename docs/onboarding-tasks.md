# 新人练手：vla-harness + RobotWin 出分（最小闭环，0-1 切分版，总 5 周）

> 原则：只给目标和验收，不给步骤不给链接。卡住了先自己想办法；
> 实在过不去带着“已试过的三条路”来问人。红线见末尾。

## W1：机器分工（2 天搭台 + 3 天熟悉）

- [ ] T1.1 任选机器数量并部署到位，能远程开关机
  - 验收：关机→开机→runner 上线→关机，全流程走通一遍
- [ ] T1.2 证明你的分工能撑住一次完整评测（不断网、不掉线）
  - 验收：连续跑通 1 个 smoke（任务不限）

## W2：镜像同步 + 官方复现

> 分界线：全用官方件（镜像/配置/支持的模型），不动一行业务胶水——只证明官方链路通。出问题找官方或环境，不找自己。

- [ ] T2.1 把评测镜像与 serve 基础镜像同步到内网仓
  - 验收：内网仓出现所需 tag，且 digest 与源一致
- [ ] T2.2 用官方镜像原样复现一次出分（不动任何配置）
  - 验收：拿到第一个 mean_success；记录三处“想改”的地方（先记着，T3 用）

## W3-W4：部署架构设计 + 重新打包

- [ ] T3.0 先画图再动手：基于 T2 用官方镜像的体验，输出部署架构设计（哪里够用、哪里要改、怎么改；最差照搬官方也算过关）
  - 验收：有一份设计文档，其中“要改的部分”必须引用 T2 阶段遇到的具体问题；完工后对照一次（看哪些被现实推翻了）
- [ ] T3.1 自行设计 serve 镜像内容（加什么自己定），打出来；起服，端口通
  - 验收：用自烘镜像跑出响应（日志 UP + 一次空请求有返回）；能讲清每一层是干嘛的

## W5：联调出分 + 总结

> T4/T5 合并：联调（通没通）和出分（数从哪来）是一回事，分两周是凑数。

- [ ] T4.1 仿真端与 serve 端连通，跑完 1 个 task×1 集，拿到 mean_success（不问多少分）
  - 验收：指出分数落盘位置与字段；复述数据流向（仿真→判分→落盘→上报）
- [ ] T4.2 总结：对照 T3.0 的设计文档，写哪些被现实推翻了、为什么
  - 验收：一份对照总结

## 红线（碰了就回滚+写检讨）

1. 不删内网仓的任何 tag
2. 不在 V100 上手装任何东西
3. GPU 一次只跑一个任务
