# How-to：伙伴接入要多久

> 目的：把"30 分钟接入"从**声称**变成**可核对的拆解**。
> 结论先说：**机械动作 3 分钟，剩下的 25 分钟是阅读、判断和填表。**

---

## 一、伙伴要碰的东西（只有三样）

| 交付物 | 体量 | 说明 |
|---|---|---|
| serve yaml | **7 行**（`extends` + 4 个字段） | 不克隆仓库，照抄上游原文改★ |
| 对接表单 | 6 段 / 约 24 个字段 | 不知道的空着，我们帮看 |
| 权重版本 | 1 行 | Hub ID + **精确 commit**（分支名不行） |

改点规模（实测 yaml 块解析）：

| 族 | yaml 行数 | 需要改的字段 | 备注 |
|---|---|---|---|
| B · DB-CogACT | 7 | **3 处**（`model_path` / `chunk_size=16` / `camera_keys`） | `script`/`extends` 不动 |
| C · X-VLA | 7 | **4 处**（`model_path` / `benchmark_profile` / `domain_id` / `chunk_size=30`） | `chunk_size` 是 30 不是 16 |

---

## 二、机械部分：实测 3 步 < 1 分钟

| 步骤 | 命令 | 实测耗时 |
|---|---|---|
| 取上游 yaml | `curl raw.githubusercontent.com/.../xvla/robotwin.yaml` | **0.94 s** |
| 改字段 | 编辑器改 1–4 处 | **< 60 s** |
| 语法/结构校验 | `python3 -c "yaml.safe_load(...)"` | **< 1 s** |

（以上是 2026-11-25 在本机实测；`curl` 走的是 raw 链接，国内可能需换镜像，时间会变。）

## 四、四个真实卡点（按发生频率）

| 卡点 | 现象 | 为什么卡 | 现在的解法 |
|---|---|---|---|
| **族别判断** | 不知道该抄 B 还是 C | 官方支持表里一个族可能多份 yaml | 文档给了对照表；没有的族要"先提需求" |
| **权重版本写成分支名** | smoke 报 `HFValidationError` / 401 | 分支会移动，复现不了 | 表单明确要求"ID + 精确 commit" |
| **动作口径错**（EE 当关节喂） | 跑满 400 步但全 0 分、零异常 | 不会报错，只出 0 | 验收三分类里专门列了这一条 |
| **私仓没授权** | 401 | 我们拉不到权重 | 表单要求给 `link-seek` 授权 |

## 五、还有一个缺口：伙伴侧无法自验

文档里写"有 GPU 可选 `vla-eval test -c <yaml>`"，但我们实测过这条路**在上游不可用**：

```
vla-eval test -c xxx.yaml --validate
→ 容器内没有 docker CLI（skip）
→ 挂宿主 docker 后，内层 vla-eval run 不接收 -c，去读 /etc/vla-eval.yaml → IsADirectoryError
```

所以伙伴只能靠**我们这边的 smoke** 代验（1 task × 1 ep，1 天内回 spec 对齐摘要）。
这不算缺陷，但要写清：**"30 分钟"指的是把材料交齐，不是"30 分钟后能拿到分"。**

## 六、诚实声明：这是文档走查，不是真人实测

本文的计时由我按文档机械走一遍得出，**没有招募真实新伙伴**。
要把它升级成"真人实测"，需要一位没接触过本仓的人按文档走一遍，并记录：

1. 从打开文档到交出 yaml 的**总时长**
2. 每节的**停留时长**（哪节最久）
3. **卡住的次数**和原因（对照第四节四类）
4. 需要问人的问题数（越少越好）

这四项拿到后，第 17 页"便捷"的表述才能从"文档声称 30 分钟"改成"实测 X 分钟"。
